# 鳥取県 3D 市町村パズル

鳥取県の市町村（19 市町村）の地形を 3D プリントできるパズルです。国土地理院の標高データから生成した STL ファイルを配布しています。

🌐 **[https://tukumanalab.github.io/tottori-puzzle/](https://tukumanalab.github.io/tottori-puzzle/)**

## 縮尺

3 段階から選べます（定義は `scripts/scales.py`）。サイトの縮尺切り替えで表示とダウンロードが切り替わります。

| キー | 縮尺 | 全体 | 最大ピース（鳥取市） | 最小ピース（日吉津村） | 枠 |
|---|---|---|---|---|---|
| `300k` | 1/300,000（等倍） | 424 × 213 mm | 149 × 110 mm | 6.5 × 9.0 mm | 3 分割 |
| `600k` | 1/600,000（1/2） | 215 × 109 mm | 74 × 55 mm | 2.9 × 4.2 mm | 一体 |
| `900k` | 1/900,000（1/3） | 145 × 75 mm | 50 × 36 mm | 1.8 × 2.5 mm | 一体 |

**縮尺で変わるのは平面の大きさと地形の起伏だけです。** 印刷のための物理寸法 — ベース厚さ 3mm・枠厚さ 4mm・ポケット深さ 2mm・クリアランス 0.3mm・境界リッジ 0.5mm・裏面の文字サイズ — は全縮尺で共通にしてあります。そのためどの縮尺でもピースと枠の嵌合は同じで、裏面の文字も同じ読みやすさになります。

メッシュの間引き（decimation）は縮尺に反比例して強めており、モデル座標でのセル寸法（約 0.21mm）は全縮尺で一定です。小さい縮尺ほどファイルも小さくなります（ピース合計: 100MB / 25MB / 12MB）。

小さい縮尺では一部のピースが極端に小さくなります。日吉津村は 1/2 で 2.9 × 4.2mm、1/3 で 1.8 × 2.5mm になり、裏面の文字が入らないため彫刻を省いています（潰れた文字を入れるより無地の方が良いため）。0.3mm のクリアランスは物理寸法なので縮尺では縮まず、小さいピースほど相対的にゆるくなります。

## 高さの強調

地形の起伏は**実寸の 3 倍**に強調しています（`scripts/scales.py` の `Z_SCALE`）。倍率が掛かるのは起伏だけで、ベース厚さ 3mm には掛かりません。枠は境界データだけから作っていて標高を使わないため、この値の影響を受けません。

等倍縮尺での起伏の例:

| 市町 | 最高標高 | 起伏 | 全高（ベース 3mm 込み） |
|---|---|---|---|
| 大山町 | 1,709m | 17.0 mm | 20.0 mm |
| 若桜町 | 1,448m | 14.3 mm | 17.3 mm |
| 日南町 | 1,218m | 12.4 mm | 15.4 mm |
| 境港市 | 12m | 0.1 mm | 3.1 mm |

## ピース仕様

- ベース厚さ: 3mm（全縮尺・全倍率で共通）

等倍は東京都パズル（1/200,000）よりやや小さいスケールです。鳥取県は東西に長く、この縮尺だと 3 分割した枠が 1 枚 152mm 幅以内に収まり、県内最大の鳥取市も一般的な 250mm 角のベッドに載ります。

## 枠（フレーム）仕様

等倍では 3 つのセクションをタブ/スロットで接続して一体の枠として使用します。分割位置は鳥取県の一般的な地域区分（西部・中部・東部）に合わせています。1/2・1/3 では全体が 1 枚のベッドに収まるため分割していません。

| 縮尺 | ファイル | 内容 | サイズ |
|---|---|---|---|
| `300k` | `frame_seibu.stl` | 西部（米子市・境港市・西伯郡・日野郡） | 152 × 213 mm |
| `300k` | `frame_chubu.stl` | 中部（倉吉市・東伯郡） | 136 × 213 mm |
| `300k` | `frame_tobu.stl`  | 東部（鳥取市・岩美郡・八頭郡） | 146 × 213 mm |
| `600k` | `frame_all.stl`   | 鳥取県全体 | 215 × 110 mm |
| `900k` | `frame_all.stl`   | 鳥取県全体 | 145 × 75 mm |

- 総厚さ: 4mm
- ポケット深さ: 2mm（ピース受け面）
- 市町村境界線: 0.5mm 盛り上がり

ラスタ解像度（`PX_SIZE`）は 0.5 / 0.4 / 0.35 mm と、縮尺ほどには細かくしていません。縮尺に比例して細かくすると、面積が減ってもピクセル数が減らず、小さい縮尺の方が三角形数が多くなってしまうためです。

## データ生成フロー

```
npm run data:fetch   # 1. 行政界 GeoJSON をダウンロード
npm run data:stl     # 2. 市町村ピース STL を生成（全縮尺）
npm run data:frame   # 3. 枠 STL を生成（全縮尺）
```

縮尺やコードを絞りたい場合:

```
python3 scripts/gen_stl.py --scale 600k           # 1/600,000 の全市町村
python3 scripts/gen_stl.py --scale 300k 31201     # 等倍の鳥取市だけ
python3 scripts/gen_frame.py --scale 300k seibu   # 等倍の西部の枠だけ
```

出力は `public/data/stl/{縮尺キー}/` 以下に分かれます。あわせて `public/data/pieces.json`（ピースごとの寸法）と `public/data/frames.json`（枠のセクション構成と寸法）を書き出し、サイトはこれを読んで表示しています。

ダウンロードするファイル名の先頭にも 2 桁ゼロ埋めで付きます（例 `01_31201_Tottori_300k.stl`）。番号順に並ぶようにするためです。**ピース裏面に彫っているのは市町村名だけで、番号もコードも入れていません。**

コードは国土数値情報 N03 の `N03_007`（全国地方公共団体コード、JIS X 0401・X 0402）で、境界ファイル名・STL ファイル名・`pieces.json` のキーにも使っています。上 2 桁が都道府県（鳥取県 = 31）、下 3 桁が市町村です。番号が飛んでいるのは平成の大合併で消えた町村のコードが欠番になっているためです。

### 1. 行政界データの取得 (`scripts/fetch-boundaries.ts`)

国土交通省 国土数値情報（N03-2024）の鳥取県データを ZIP でダウンロードし、市町村コードごとに GeoJSON ファイルとして保存します。

- 出力先: `public/data/boundary/{code}.json`
- 対象は 4 市 14 町 1 村の 19 市町村
- 同一コードの複数ポリゴンは共有頂点でつながる本土側の連結成分のみを採用（岩美町の 524 の岩礁など、離島・飛び地を除外）

### 2. ピース STL の生成 (`scripts/gen_stl.py`)

各市町村の境界 GeoJSON と国土地理院の DEM（数値標高モデル）タイルから、3D メッシュを生成します。

#### 座標変換

地理座標（緯度経度）をミリメートル座標に変換します。

```python
PROJ_CENTER_LAT = 35.35
PROJ_CENTER_LON = 133.83
XY_SCALE = 1.5 / 450  # 1/300,000

x = (lon - 133.83) * cos(35.35°) * 111320 * XY_SCALE  # 東西
y = (lat - 35.35)  * 111320 * XY_SCALE                 # 南北
```

#### DEM タイルの取得

国土地理院の XYZ タイル（テキスト形式 DEM）を HTTP で取得します。

- URL: `https://cyberjapandata.gsi.go.jp/xyz/dem/{z}/{x}/{y}.txt`
- 標準ズームレベル: 13（約 15m 解像度）
- 県内最大の鳥取市（765km²）のみズーム 12（約 31m）に切り替え
- 取得したタイルはキャッシュ（`public/data/dem/`）に保存し再利用。縮尺が違っても同じタイルを使うため、2 つ目以降の縮尺ではダウンロードが発生しません

#### メッシュ生成

1. 市町村の bounding box を覆うタイルを結合してラスタ標高グリッドを構築
2. 境界ポリゴンをラスタライズし、市町村外をマスク
3. 外周を 0.3mm 分だけ収縮（枠側の 0.3mm と合わせて 0.6mm の遊び）
4. グリッドを間引き（decimation）してポリゴン数を削減
   - 面積の大きい市町は間引きを強め、県内最小の日吉津村は細かくして裏面文字の解像度を確保
5. 上面（地形面）・側面・底面を三角形メッシュに変換
6. 底面の裏側に市町村名を浮き彫り

上面・側面・底面はすべて同じセル格子（`cell_grid`）から生成しています。判定基準が
ずれると外周が噛み合わず穴だらけのメッシュになるためです。また彫刻テキストは
外周に接するセルから除外しています（窪みが側面に達すると底面の段差と側壁の下端が
噛み合わなくなるため）。生成後は全 62 ファイルについて、符号付き体積が正・全法線が巻き順と一致・穴（奇数重
エッジ）ゼロであることを確認しています。ピクセル由来のメッシュに付きものの対角接触
（4 重エッジ）が全体で 65 箇所ありますが、面は閉じており印刷に支障はありません。

#### 裏面の文字入れ

市町村名を裏面から読めるよう左右ミラーで彫刻します。文字の置き場所は積分画像で厳密に決めています。

1. 行高さ 8mm でテキストのビットマップを生成
2. そのビットマップと同じ大きさの矩形が市町村の内側に完全に収まる位置を全探索（積分画像で O(N)）
3. 収まる位置があればその中で重心に最も近い位置に配置。なければ行高さを二分探索で縮める
4. 2 行に折り返した方が大きく収まる場合は 2 行レイアウトを採用（例: 日吉津村 →「日吉 / 津村」）

市町村の重心は L 字型や細長い形だと領域の外や細い部分に落ちるため、単純な重心配置では米子市・伯耆町のように文字が 2〜3mm まで縮んでしまいます。矩形の収まりを直接判定することで、19 市町村中 17 市町村が上限の 8mm で入ります。

### 3. 枠 STL の生成 (`scripts/gen_frame.py`)

全 19 市町村の輪郭を組み合わせたトレイ型の枠を生成します。

#### グローバルグリッド

全市町村を単一のピクセルグリッド（0.5mm/px）に投影し、3 つのセクションをスライスして分割します。

```
[ seibu ] | [ chubu ] | [ tobu ]
          ↑           ↑
      x = -66mm    x = +65.5mm
```

分割位置は、西部の東端（大山町 -67.1mm）と中部の東端（三朝町 +64.3mm）のそれぞれ 1mm 外側です。これにより西部・中部の全ピースは各セクション内に収まり、境界をまたぐのは鳥取市（中部側に約 30mm）と琴浦町（西部側に約 16mm）だけになります。座標は等倍基準で、他の縮尺では縮尺比で換算します。

#### ラスタライズ

各セクションで **全 19 市町村** のポリゴンをラスタライズします（担当地域以外も含む）。これにより、セクション境界をまたいで延びる市町村の輪郭も正しくくり抜かれます。

- クリアランス: 0.3mm（`scipy.ndimage.binary_dilation` で拡張）
- 境界リッジ: 隣接する異なる市町村のピクセルを検出し、床面から 0.5mm 盛り上げ

#### 断面構造

```
z=4mm ───┐    ┌──── 枠上面
         │    │
z=2.5mm  │  ┌─┘──── 境界リッジ
z=2mm ───┘  ╔╝───── ピース受け面
            ║
z=0mm ──────╚─────── 底面（フラット）
```

#### タブ/スロット接続

セクション間をタブ（雄）とスロット（雌）で嵌め合わせる構造です。

- タブ: 左セクション右端から 5mm 突出、高さ 15mm を繰り返し
- スロット: 右セクション左端をくり抜き（クリアランス 0.3mm）
- 配置行は両セクションともフレーム素材がある行に限定

## 開発環境

### 必要なツール

- Node.js 20+
- Python 3.x
- `pip install numpy Pillow scipy`

### セットアップ

```bash
npm install
npm run data:fetch   # 境界データ取得（初回のみ）
npm run data:stl     # ピース STL 生成（DEM タイルの取得を含む）
npm run data:frame   # 枠 STL 生成
npm run dev          # 開発サーバー起動
```

生成物は 3 縮尺あわせておよそ 255MB（ピース 57 ファイル 136MB + 枠 5 ファイル 119MB）になります。DEM タイルのキャッシュ（`public/data/dem/`）に別途 91MB 使います。

### CI/CD

`main` ブランチへの push で GitHub Actions が自動でデータ生成・ビルド・デプロイを実行します。スクリプトが変更されていない場合はキャッシュからデータを復元するため、2 回目以降は高速です。
